# Ploos AS

**Open hardware, software and learning material for people who want to understand, build and preserve computers.**

Ploos AS is a Norwegian technology company and open-source organization working across retro computing, computer architecture, electronics, software, networking and technical education.

We build tools for classic computer platforms, design open computers and hardware, create software and infrastructure, and develop learning material that explains computers from the fundamentals upward.

Our goal is not only to make things that work, but to make technology **understandable, reproducible, repairable and open to study**.

🌐 [ploos.no](https://www.ploos.no/)

---

## What we work on

Our work spans several areas:

- **Retro computing** — software, hardware, preservation, networking, development tools and modern infrastructure for classic systems.
- **Open computer hardware** — computers, expansion hardware, interfaces, FPGA designs and electronics intended to be studied, modified and built.
- **Systems software** — operating-system components, networking software, utilities, development environments and infrastructure.
- **Computer education** — courses, books, simulators, emulators and practical exercises covering programming, electronics and computer architecture.
- **Networking and communications** — Internet protocols, BBS systems, IRC, terminal systems and the technologies that connect computers.
- **Security and diagnostics** — tools for understanding, testing, maintaining and protecting computer systems.
- **Preservation** — keeping older platforms, software, knowledge and development practices usable on modern systems.

We are particularly interested in the space where **retro computing, education and modern open-source development meet**.

## Our principles

### Open by default

Whenever possible, our work is published with source code, design files and documentation available for inspection and modification.

We believe that being able to study how something works is an important part of owning and understanding technology.

### Learn by building

Many of our projects are designed not only to solve a problem, but also to explain it.

A compiler, emulator, computer, network stack or circuit can be useful in its own right — and also serve as a practical way to learn how computers work.

### Understand the whole system

We are interested in the complete stack:

**electronics → digital logic → processors → machine code → operating systems → networking → applications**

Modern systems often hide these layers. We like making them visible again.

### Preserve, don't just emulate

Retro computing is more than nostalgia.

Classic systems provide unusually accessible environments for learning computer architecture, operating systems, graphics, networking and programming.

Preserving these systems also means preserving the knowledge required to understand and develop for them.

### Build things that can be studied

Where practical, we prefer designs that are:

- documented
- reproducible
- testable
- repairable
- understandable
- friendly to hobbyists and students

Complexity is sometimes unavoidable, but unnecessary complexity is not a goal.

## Open-source licensing

Our default licensing model is:

| Material | Default license |
| --- | --- |
| Hardware, PCB designs and HDL | **CERN-OHL-P-2.0** |
| Software and source code | **MIT** |
| Documentation and educational material | **Creative Commons** |

Some repositories include third-party components or have requirements that call for different licenses.

The license files in each repository are authoritative.

## Project maturity

Projects in this organization range from experiments and research prototypes to mature tools and released software.

Some hardware projects may have complete specifications, simulations or design files before physical hardware has been manufactured.

Each repository documents its own current status, milestones and known limitations.

If you are planning to build hardware, deploy software or depend on a project, check that repository's README and release information first.

## Reproducibility and testing

We aim to make projects reproducible wherever practical.

Depending on the project, this may include:

- automated tests
- emulators and simulators
- containerized development environments
- CI builds
- hardware validation
- reference test vectors
- documented build procedures
- release artifacts

For retro platforms in particular, we try to combine emulation-based testing with testing on real hardware when hardware is available.

# Norsk

**Åpen maskinvare, programvare og læremateriell for dem som ønsker å forstå, bygge og bevare datamaskiner.**

Ploos AS er et norsk teknologiselskap og en open-source-organisasjon som arbeider med retrodatamaskiner, datamaskinarkitektur, elektronikk, programvare, nettverk og teknisk undervisning.

Vi utvikler verktøy og programvare for klassiske datamaskinplattformer, designer åpne datamaskiner og elektronikk, bygger infrastruktur og lager undervisningsmateriell som forklarer hvordan datamaskiner fungerer — fra grunnleggende elektronikk til programvare og nettverk.

Målet er ikke bare å lage ting som fungerer, men teknologi som er **forståelig, reproduserbar, reparerbar og åpen for å studeres**.

## Hva vi arbeider med

Arbeidet vårt omfatter blant annet:

- retrodatamaskiner og bevaring
- åpne datamaskiner og elektronikk
- systemprogramvare
- programmering og utviklingsverktøy
- nettverk og kommunikasjon
- simulatorer og emulatorer
- sikkerhet og diagnostikk
- kurs, bøker og annet undervisningsmateriell

Vi er spesielt interessert i området der **retrodatabehandling, undervisning og moderne open-source-utvikling møtes**.

## Prinsipper

Vi forsøker å publisere kildekode, designfiler og dokumentasjon åpent når det er mulig.

Vi mener at teknologi blir mer verdifull når brukeren også kan forstå hvordan den fungerer.

Derfor liker vi prosjekter der man kan følge hele kjeden:

**elektronikk → digital logikk → prosessor → maskinkode → operativsystem → nettverk → applikasjoner**

Mange moderne systemer skjuler disse lagene. Vi ønsker å gjøre dem synlige igjen.

## Lisensiering

Som hovedregel bruker vi:

- **CERN-OHL-P-2.0** for maskinvare, PCB-design og HDL
- **MIT** for programvare og kildekode
- **Creative Commons** for dokumentasjon og undervisningsmateriell

Enkelte prosjekter kan bruke andre lisenser på grunn av avhengigheter eller eksisterende opphavsrett.

Lisensfilene i hvert enkelt repository er alltid gjeldende.

## Bidrag

Issues, testing, dokumentasjon, kode, maskinvaretesting, kompatibilitetsrapporter, oversettelser og andre bidrag er velkomne.

For spørsmål eller bidrag til et konkret prosjekt, bruk issue-trackeren i det aktuelle repositoryet.

Testing på ekte retro-maskinvare er spesielt verdifullt.
